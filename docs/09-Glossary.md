# Glossary — Leish! v2

| Term                              | Definition                                                                                                                                                                                                                                                             | Source                                                     |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **Admin**                         | Platform operator with `role='admin'`; can access `/admin/*` and `/api/admin/*`; all mutations audit-logged to `admin_audit_log`.                                                                                                                                      | `src/server/admin-auth.ts`, `src/lib/types.ts:1`           |
| **Agnost AI**                     | Analytics SDK (`agnostai`) initialized at startup (`src/instrumentation.ts`) and client (`src/lib/agnost-client.ts`); tracks register/login/booking/quotation/payment/profile-edit; dashboard `3e27e121…`.                                                             | `src/server/agnost.ts`                                     |
| **Artist**                        | Role `artist`; MUA serving customers; must claim a catalog profile (`artist_profiles`) to receive/act on bookings.                                                                                                                                                     | `src/lib/types.ts:1`                                       |
| **Balance**                       | `payments.type='balance'` — second payment = `quotation.total - deposit`; due **3 days before** event (`balanceDueDate`); when paid triggers payout. Non-refundable as deposits are, but balance is refundable on cancelled bookings.                                  | `src/server/payments.ts:30`                                |
| **Billplz**                       | Malaysian hosted payment gateway API v3; configured via `BILLPLZ_API_KEY`, `BILLPLZ_COLLECTION_ID`, `BILLPLZ_BASE_URL`; bills created at `POST /bills` with HMAC webhook `X-Billplz-Signature`. Fallback `provider='dev'` when not configured.                         | `src/server/payments.ts:49`, `src/lib/payments/billplz.ts` |
| **BridalEvent**                   | Enum `engagement\|solemnization\|reception\|full-package\|bridal-other`; used in artist tags and `BRIDAL_EVENTS` list.                                                                                                                                                 | `src/lib/types.ts:3`, `src/lib/data.ts:76`                 |
| **Booking**                       | Central entity (`bookings` table) with `id,user_id,artist_id,studio_id,artist_name,service,price,date,time,notes,event_type,venue,guest_count,status`; status state machine `requested→accepted→confirmed→completed\|cancelled`; slot guarded by partial unique index. | `src/server/db.ts:219`, `src/server/bookings.ts`           |
| **Booking Fee / Deposit**         | Flat non-refundable amount `booking_fee_sen` (default RM50 = 5000 sen) — first payment to **confirm** an `accepted` booking; platform-kept; configured in `platform_settings`.                                                                                         | `src/server/settings.ts:21`                                |
| **Budget**                        | Filter on `listArtists` (`budget` → SQL `price_from <= budget`); integer sen equivalent client sends MYR.                                                                                                                                                              | `src/server/catalog.ts:211`                                |
| **Catalog**                       | DB tables `artists,studios` (runtime source of truth); `src/lib/data.ts` `SEED_ARTISTS/STUDIOS` are **seed-only**; catalog repository `src/server/catalog.ts` (auto-seeds via `ensureCatalogSeeded`).                                                                  | `AGENTS.md §1`                                             |
| **Claim**                         | Linking a platform user to a catalog entity: `artist_profiles(user_id→artist_id)` or `studio_profiles`; scopes `GET /api/bookings` to claimed ids (`getClaimedArtistIds`).                                                                                             | `src/server/artist-profiles.ts`                            |
| **Client / Customer**             | Role `customer`; external user booking services; only owner of booking can pay/cancel.                                                                                                                                                                                 | `src/lib/types.ts:1`                                       |
| **Commission**                    | Platform keep computed by `computeCommission(totalSen, rateBps, waiverSen)` — waived when `total < waiver`; otherwise `round(total*rate/10000)`; deducted from payout (not added to client price).                                                                     | `src/server/settings.ts:100`                               |
| **CSP (Content Security Policy)** | Per-request nonce CSP set in `next.config.ts`; no `unsafe-inline` for scripts (theme inline uses nonce) plus `X-Frame-Options:DENY`, etc.                                                                                                                              | `next.config.ts`                                           |
| **DbFacade**                      | Two-backend DB abstraction `getDb(): DbFacade {prepare,exec}` hiding PG (`pg.Pool`) vs SQLite (`node:sqlite DatabaseSync`); placeholder translation `@name/? → $n`; `getDb()` synchronous.                                                                             | `src/server/db.ts:24`                                      |
| **Deposit**                       | Alias for **Booking Fee** (flat RM50). `payments.type='deposit'`.                                                                                                                                                                                                      | —                                                          |
| **Dev Provider**                  | `provider='dev'` — synthetic payment row with `provider_ref=dev_…` and no Billplz call; webhook auto-settled in tests for e2e; never charges real money.                                                                                                               | `src/server/payments.ts:77`                                |
| **Email Outbox**                  | Table `email_outbox` sink for `EMAIL_PROVIDER=dev`; viewable at `/dev/emails` (dev only).                                                                                                                                                                              | `src/server/email.ts`                                      |
| **Event Type**                    | `event_type` on bookings (bridal/non-bridal taxonomy label); `venue`, `guest_count` sibling fields.                                                                                                                                                                    | `src/server/validation.ts:28`                              |
| **FRS**                           | Functional Requirements Specification (`docs/03-FRS-…`); per-module `FR-xxx` with acceptance criteria.                                                                                                                                                                 | —                                                          |
| **Guest**                         | Unauthenticated visitor; can browse catalog but is redirected for booking/auth actions.                                                                                                                                                                                | —                                                          |
| **BRS / BRD**                     | Business Requirements Specification (`docs/01-BRS-…`); business-level `BR-xx`, `BRL-xx`.                                                                                                                                                                               | —                                                          |
| **NFR**                           | Non-Functional Requirements (`docs/04-NFR-…`) covering performance, security, reliability etc.                                                                                                                                                                         | —                                                          |
| **JT I / JWT**                    | JWT with JTI revocation table `sessions(jti,revoked)`; HS256 via `jose`; cookie `leish_session` 7-day TTL.                                                                                                                                                             | `src/server/session.ts`                                    |
| **NonBridalEvent**                | Enum `dinner\|graduation\|ceremony\|corporate\|touch-up\|non-bridal-other`; `NON_BRIDAL_EVENTS`.                                                                                                                                                                       | `src/lib/types.ts:6`                                       |
| **Payout**                        | Settlement row (`payouts`: `gross,commission,net,status pending→settled\|failed,settleable_at=event+24h`) created when balance is paid; `net = gross - commission - deposit`; admin settles via `/admin/payouts`.                                                      | `src/server/payouts.ts:56`                                 |
| **PDPA**                          | Malaysia Personal Data Protection Act 2010 — consent (`users.consent`), export (`/api/me/export`), delete (`DELETE /api/me`), retention per `docs/PDPA_RETENTION_GUIDELINES.md`.                                                                                       | —                                                          |
| **Platform Settings**             | `platform_settings` key/value store runtime-configurable by admin: `booking_fee_sen`, `commission_rate_bps` (0–5000 bps, clamp), `commission_waiver_sen` (default RM100). Cached 30s.                                                                                  | `src/server/settings.ts:39`                                |
| **Pre-Check vs Index**            | Booking slot pre-`SELECT` friendly 409 + race `catch` on `UNIQUE`/`duplicate key` — hard guarantee is DB partial index `uq_bookings_slot`.                                                                                                                             | `src/app/api/bookings/route.ts:217`                        |
| **Quotation**                     | Line-item price breakdown (`quotations`: base/travel/earlyCall/accommodation + extras) with `total` sen; `status pending‖expired‖superseded‖paid`; TTL 24h (`QUOTATION_TTL_MS`); re-quote supersedes.                                                                  | `src/server/quotations.ts:13`                              |
| **RTM**                           | Requirements Traceability Matrix (`docs/08-Traceability-Matrix.md`); BR→SRS→FRS→API→DB→test.                                                                                                                                                                           | —                                                          |
| **SRS**                           | Software Requirements Specification (`docs/02-SRS-…`); SRS-F features with §4 external interfaces.                                                                                                                                                                     | —                                                          |
| **SSE**                           | Server-Sent Events `text/event-stream` for per-booking chat: `GET /api/bookings/[id]/messages/stream` via `chat-bus`.                                                                                                                                                  | `src/server/chat-bus.ts`                                   |
| **State Machine**                 | `applyBookingTransition(current,action,{isOwner,role})` + `confirmOnFeePaid` defining valid transitions (diagram in FRS §20).                                                                                                                                          | `src/server/bookings.ts:40`                                |
| **Studio**                        | Role `studio` and catalog `studios` table; may have distinct flow in future but today shares Artist flows scoped by `studio_id` when claimed; seed holds 4 studios.                                                                                                    | `src/lib/types.ts:1`                                       |
| **Terms of Reference**            | `BR`, `SRS-F`, `FR`, `NFR`, `UC`, `US`, `BRL` naming convention across docs.                                                                                                                                                                                           | —                                                          |
| **Turnstile**                     | Cloudflare Turnstile bot protection widget (`TurnstileWidget`) + server verify (`TURNSTILE_SECRET_KEY`); required on `pay-fee/balance` when configured.                                                                                                                | `src/components/TurnstileWidget.tsx`                       |
| **Use Case / User Story**         | `UC-xx` (Cockburn steps) and `US-xx` (INVEST) in `docs/05-Use-Cases-and-User-Stories.md`.                                                                                                                                                                              | —                                                          |
| **Verification**                  | `email_verifications` — hashed single-use token for email verification; shown in `/dev/emails` in dev.                                                                                                                                                                 | `src/server/db.ts:246`                                     |
